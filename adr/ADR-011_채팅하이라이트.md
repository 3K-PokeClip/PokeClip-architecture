# ADR-011: 채팅 수집·하이라이트 탐지

- **상태**: 채택 (알고리즘 상세 파라미터는 미결 — 멘토 협업 안건)
- **결정일**: 2026-07-20
- **관련**: [ADR-002](ADR-002_OBS플러그인.md) · [ADR-007](ADR-007_스택배치.md)
- **반영 산출물**: 3_SA · 4_SysA · **상세판: [8_Pokeclip_하이라이트연구노트.md](../8_Pokeclip_하이라이트연구노트.md)**

## 컨텍스트

채팅을 어떻게 수집하고(플랫폼별 API 제약), 채팅에서 하이라이트를 어떻게 산정할 것인가. 기존 자산(streaming-chat-collector)의 활용 방식 포함.

## 결정 — 수집

치지직 공식 Open API(Session 웹소켓)를 기본, 비공식 WS를 폴백으로(SOOP은 비공식 WS). 수집은 SRT 인제스트 이벤트로 자동 트리거(온보딩에서 등록한 채널 대상, 본방 미개시 대비 라이브 폴링+백오프). 플랫폼별 반응 시차를 보정해 인제스트 타임라인에 정렬. 하이라이트는 채팅 차트 분석(이동평균 대비 급등·스파이크 계열, 주식 차트 분석 현직 멘토와 협업)으로 산정.

**근거**
- 방식 3분류 비교: ①공식 API(안정·약관 안전) ②비공식 WS 직결(가볍지만 프로토콜 변경 리스크) ③브라우저 DOM 스크래핑(채널당 브라우저 필요, 서버 상시 수집 부적합) → ①+② 조합이 정답이며 기존 수집기가 이미 이 구조.
- 시차 보정이 필요한 이유: 플랫폼마다 방송 지연이 달라 같은 장면의 채팅 반응 도착 시각이 어긋남 — 보정 없이 합치면 스파이크가 뭉개져 탐지 정확도 하락.
- 기존 자산(streaming-chat-collector) 리팩토링 항목: 인메모리 상태→Redis 외부화 / 수동 연결→이벤트 구동 / 시차 보정 훅 / JSONL→S3 채팅 아카이브 / frameCapture 제거(원본 영상 보유로 불필요) / 분석 UI는 대시보드 라이브 뷰로 흡수.

## 결정 — 채팅 신호 모델 (팀 실측 연구 기반, 2026-07)

- 채팅은 두 종류다: **반응 채팅**(화면 사건에 대한 반응 — 하이라이트 신호원)과 **소통 채팅**(스트리머와의 대화 목적 — 잡음원).
- 채널 유형별 실측: **대형은 참여율 1~2%임에도 하이라이트가 깨끗하게 잡힌다**(소통 동기가 약해 반응 위주 → S/N 양호). **소통 중심 채널(참여율 3~5%, 예: 여성 스트리머)은 하이라이트가 아니어도 참여율이 상시 높아 베이스라인이 오염**된다 — 거래량은 많지만 방향성 없는 횡보장과 유사. 여기가 주식 차트 분석 기법(현직 멘토 협업)이 필요한 구간.
- **소형 채널은 채팅이 거의 전부 소통 채팅 + 절대량 부족** → 채팅 단독 하이라이트 탐지는 현재로선 신뢰 불가 판단. 데이터 축적 후 재검토하는 **미확정 연구 과제**로 남긴다(설계 전제로 삼지 않음).
- 탐지 가설: 메시지 수보다 **고유 채터 수의 급증**이 더 깨끗한 신호 후보 — 1인 도배는 메시지 수만 올리고, 진짜 하이라이트는 눈팅층이 동시에 입을 여는 순간(거래량이 아닌 '참여 계좌 수' 관점).
- **자동 하이라이트 활성 정책**: 단순 채팅량 임계가 아니라 **채널 프로파일 기반 신뢰도**(참여율·소통성 베이스라인 채널별 학습)로 판단. 신뢰도 미달 채널은 자동 탐지를 정직하게 비활성화하고 **핫키 모드 안내** — 엉터리 카드를 뿌리는 것보다 신뢰를 지키는 UX. 소형 유저는 핫키·원클릭·BGM 제거·AI 자막 등 채팅량 무관 기능을 사용(수동 모드), 채널 성장 시 자동 탐지가 "켜지는" 업셀 경로.

## 결정 — 베이스라인 방법론 (팀 실측, 5초 윈도우 실험)

- **평균 vs 중앙값**: 대규모 방송에서 채팅 전체 평균은 방송 내내 안정적 — 스파이크는 시간적으로 희소해(수 시간 방송 중 수십 초) 평균을 거의 못 흔든다. 따라서 "나중에 더 큰 스파이크가 나오면 기존 구간의 배율이 강등되지 않을까"는 실측상 기우이며, **배율 임계(평균 대비 2~3배)가 방송 내내 안정 작동**. 평균이 강건하므로 중앙값의 오염 저항 이점이 소멸 → 더 단순한 평균 채택.
- **사후 vs 실시간 구분**: 전체 평균은 사후에만 확정되는 값. 실시간 탐지는 누적/롤링 평균을 쓰되 **초반 워밍업 구간(베이스라인 학습, 카드 발행 보류)** 필요. 누적 평균이 안정적인 전체 평균에 수렴하므로 워밍업 후엔 동일 임계 사용 가능.
- **베이스라인 드리프트 예외**: 시청자 수가 방송 중 급변(레이드 유입 등)하면 전체 평균 기준이 왜곡 → **롤링 베이스라인(최근 10~20분) 병용** — 장기/단기 이평선 병용 구조(차트 분석 멘토 협업 안건).
- **멀티윈도우 합의**: 수집기가 이미 1/3/5/10초 윈도우를 지원하므로, 복수 윈도우에서 동시 검출된 스파이크만 카드로 승격하는 앙상블로 오탐 저감(추가 구현 비용 최소).

## 미결 (멘토 미팅 안건 — 연구노트 §7)

배율 임계 K의 채널별 값 / 롤링 창 길이 W / 창 내 통계량(트림 평균 vs 중앙값) / 국면 전환 카드화 여부 / 고유 채터 수 A/B / 소형 채널 대체 신호.
