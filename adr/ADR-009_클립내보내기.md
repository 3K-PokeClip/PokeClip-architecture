# ADR-009: 클립 내보내기 파이프라인

- **상태**: 채택
- **결정일**: 2026-07-20
- **관련**: [ADR-008](ADR-008_VAD제거.md) · [ADR-010](ADR-010_유튜브업로드.md) · [ADR-012](ADR-012_계정권한.md)
- **반영 산출물**: 1_IA · 2_UserJourney · 3_SA

## 컨텍스트

클립을 어떤 방식으로 잘라 내보낼 것인가 — 화질(스마트 컷 vs 재인코딩), 화면비율, 오디오 처리, 자막 방식, 편집 결과의 재사용성이 한 묶음의 결정.

## 결정 묶음

- **항상 재인코딩**: 크롭·상하분할·자막 번인이 어차피 픽셀을 다시 그림 — 예외 경로(smart cut)는 복잡도 낭비. 40초 1080p 클립 재인코딩은 수 초.
- **화면비율 5종 = FFmpeg 필터그래프 레시피** (가로/세로 9:16/1:1/상하분할 vstack/장면캡쳐 crop), 에디터의 크롭 좌표가 파라미터.
- **오디오**: 선택 트랙 amix(트랙별 볼륨) → **-14 LUFS 노멀라이즈**(유튜브 기준) → 스테레오 AAC.
- **클립 길이 5초~3분**: 상한을 유튜브 Shorts 한도에 정렬(세로형 ≤3분은 자동 Shorts).
- **자막 = 번인 기본 + CC 등록**: 숏폼은 무음 시청이 많아 번인이 표준. CC 트랙 병행 등록으로 자동번역·검색·접근성 확보. 모드는 레시피 항목(굽기+CC/굽기만/CC만) — 시청자가 자막을 끌 수 있게 하려면 CC만 모드 선택.
- **레시피 JSON 저장(논디스트럭티브)**: 클립 = 레시피(구간·크롭·트랙·볼륨·자막 스타일·제목) + 렌더 결과물. 오타 수정·가로/세로 두 벌 뽑기가 재렌더 한 번. 핫키 자동 업로드의 템플릿 = 구간이 비어 있는 레시피(데이터 모델 통일).
- **미리보기는 클라이언트**(video + CSS/canvas 시뮬레이션), 서버는 저장 시 최종 렌더만. 렌더·업로드는 비동기 잡 큐(상태·진행률·재시도).

## 검토한 대안

- **Smart cut(키프레임 경계 무손실 컷) 병행**: 필터가 없는 순수 컷에서만 성립하는 예외 경로 — 크롭·자막·비율 변환이 기본인 우리 플로우에선 적용 구간이 거의 없고 코드 경로만 2배 → 탈락.
- **번인 없이 CC만 기본**: 숏폼 무음 시청 환경에서 자막 노출이 플랫폼 재량에 좌우됨 → 번인 기본 유지, CC만 모드는 레시피 옵션으로 제공.
