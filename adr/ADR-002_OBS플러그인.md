# ADR-002: OBS 플러그인 직접 개발 (C++)

- **상태**: 채택
- **결정일**: 2026-07-20
- **관련**: [ADR-001](ADR-001_송출프로토콜.md) · [ADR-008](ADR-008_VAD제거.md) · [ADR-011](ADR-011_채팅하이라이트.md)
- **반영 산출물**: 0_UseCase · 1_IA · 3_SA · 4_SysA
- **갱신(2026-07-23)**: 오디오 트랙 상한을 **6(네이티브)**로 확정(원안 "~10트랙"에서 완화). 아래 컨텍스트·근거·대안 평가에 반영. 상세: [`pokeclip-obs-plugin` ADR-6track](https://github.com/xodbs1021/pokeclip-obs-plugin/blob/master/docs/pokeclip/ADR-6track.md).

## 컨텍스트

OBS 내장 출력(Custom FFmpeg Output)만으로 멀티오디오(6트랙)·전역 핫키·자동 재연결 요구를 충족할 수 있는가, 아니면 플러그인을 직접 개발해야 하는가.

## 결정

OBS 내장 출력 대신 자체 플러그인을 C++(libobs·FFmpeg 라이브러리·libsrt)로 개발한다.

## 근거 — 플러그인이 없으면 잃는 것들

- **오디오 6트랙(네이티브)**: 오디오는 OBS 믹서의 6트랙(MAX_AUDIO_MIXES) 안에서 각 소스를 개별 트랙에 라우팅해 해결한다 — 트랙0=최종 믹스(시청용), 1~5=소스별(편집용). 트랙 슬롯이 고정이라 PID가 방송 내내 안정적이고 소스 비활성 시 무음이 연속된다. **이 항목 자체는 플러그인 없이도 가능**하지만, 플러그인이 소스→트랙 자동 매핑과 공유 인코더 송출을 함께 처리한다. (>6이 필요해지면 `obs_source_add_audio_capture_callback`로 믹서를 우회해 확장 — 상세: `pokeclip-obs-plugin/docs/pokeclip/ADR-6track.md`.)
- **핫키 하이라이트 마킹**: OBS 단축키 시스템(전역 동작, 게임 풀스크린 OK)에 등록하려면 플러그인 필수. 방식은 단발+프리롤 — 누른 시점 T 기준 [T−30초, T+10초], 프리롤 길이는 템플릿 설정값.
- **자동 재연결**: OBS 내장 Custom FFmpeg 출력은 끊기면 수동 재시작(문서로 확인된 한계).
- **트랙 매니페스트·컨트롤 채널**: 트랙 라벨("마이크","디스코드")과 핫키 이벤트는 TS 밖 별도 컨트롤 채널(HTTPS)로 서버에 전달. TS 표준 언어 디스크립터는 ISO 언어코드용이라 부적합.
- **무설정 UX**: 내장 출력은 muxer 설정 문자열을 스트리머가 직접 입력해야 함. "설정? 할 게 없는데"라는 방송 전 경험이 서비스 셀링포인트.

## 검토한 대안 (언어 포함)

- **OBS 내장 출력 활용**: 오디오 6트랙은 내장 출력으로도 가능하나, 나머지 4개(핫키·자동 재연결·컨트롤 채널·무설정 UX) 미충족 → 탈락.
- **플러그인 언어**: libobs가 C API라 사실상 C/C++ 강제. 단, 범위가 좁아(캡처 콜백+인코더+먹싱+SRT 송신) 미디어 서버 전체를 C++로 짜는 것과는 난이도가 다르며, OBS 공식 플러그인 템플릿 존재.
