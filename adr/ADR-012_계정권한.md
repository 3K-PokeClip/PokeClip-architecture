# ADR-012: 계정·권한 모델

- **상태**: 채택
- **결정일**: 2026-07-20
- **관련**: [ADR-009](ADR-009_클립내보내기.md) · [ADR-010](ADR-010_유튜브업로드.md)
- **반영 산출물**: 0_UseCase · 1_IA

## 컨텍스트

스트리머-편집자 협업의 로그인·권한 체계. "편집자에게 자동 업로드 권한까지 줄 수 있어야 한다"는 요구와, 유튜브 API가 채널 초대 사용자를 지원하지 않는 제약(ADR-010)을 함께 만족해야 한다.

## 결정

구글 로그인 단일(OAuth, 유튜브 연동과 일원화 — 편집자는 채널 연동 불필요). 스트리머가 편집자를 초대하고 권한을 부여: 기본(라이브 뷰·클립 제작) / 토글① 직접 업로드(없으면 업로드 시도 → 승인 대기함) / 토글② 원클릭 자동 업로드(①을 전제로 하는 상위 권한, 없으면 버튼 비활성). 템플릿 수정은 스트리머 전용. 승인 대기함은 스트리머에겐 승인·반려, 편집자에겐 '내 요청 목록'으로 표시.

## 근거

- 유튜브 업로드가 구글 OAuth를 요구하므로 로그인도 구글로 일원화 — 스트리머는 한 흐름으로 로그인+채널 연동, 편집자는 로그인만(업로드는 항상 스트리머 토큰이라 편집자 채널 연동 자체가 불필요, ADR-010).
- 자동 업로드는 '사람 검토 없이 나가는' 권한이라 직접 업로드보다 상위로 계층화(②는 ① 전제). 치지직의 권한 계층 UX를 참조.
- 권한 없는 편집자의 업로드 시도는 차단이 아니라 승인 대기함으로 흘림 — 협업 흐름을 끊지 않으면서 통제 유지.

## 검토한 대안

- **유튜브 스튜디오 초대(채널 권한 위임)에 편승**: API 미지원으로 불가 → 서비스 내부 권한 체계로 대체(ADR-010과 동일 근거).
- **복수 소셜 로그인 제공**: 계정 연결 복잡도·온보딩 마찰만 증가, 어차피 업로드에 구글 동의 필요 → 탈락.
